# 云服务器部署指南（Ubuntu 26.04 / 4 核 4G）

面向**公网单机部署**：一台 x86_64 Ubuntu 26.04 LTS（4 核 4G），中间件（PostgreSQL + pgvector / Redis / 对象存储）使用云端实例，本机只跑**一个 Java 进程**（前端静态资源已打进 jar）。

预期定位：使用人数不多、并发 5 以内。

---

## 0. 部署架构

```
                    ┌──────────────────────────────────────────┐
   浏览器 ──HTTPS──▶│  Nginx (443, TLS 终止)                    │
   (仅开放         │    ├─ /            → 反向代理             │
    22/80/443)     │    ├─ /api/**      → 反向代理             │
                    │    └─ /ws/**       → 反向代理 + Upgrade    │
                    └──────────────┬───────────────────────────┘
                                   │ HTTP 127.0.0.1:8080（不对外暴露）
                    ┌──────────────▼───────────────────────────┐
                    │  Spring Boot (app.jar)                    │
                    │    前端静态资源已内置，无需单独部署         │
                    └──────────────┬───────────────────────────┘
                                   │
              ┌────────────────────┴────────────────────┐
              ▼                    ▼                    ▼
        云端 PostgreSQL       云端 Redis           云端对象存储
        (含 pgvector)       (会话 + 限流)        (RustFS / S3)
```

**为什么不需要单独部署前端**：`bootJar` 会把 `frontend/dist` 同步进 `classpath:/static`，由 `SpaWebConfig` 做 SPA 路由兜底。前端全部走相对路径 `/api/*`，同源托管下无需 Vite 代理，也无需 CORS。

## 1. 本机构建（不要在服务器上构建）

服务器只有 4G 内存，而构建需要 Gradle 守护进程（约 640MB）+ 编译 worker + pnpm 构建，容易触发 OOM。**在本地构建好再上传**。

在项目根目录执行：

```powershell
.\gradlew.bat :app:bootJar --no-daemon
```

`bootJar` 会自动串联 `buildFrontend`（`pnpm run build`）与 `syncFrontendStatic`，产物固定为：

```
app/build/libs/app.jar
```

确认产物存在且体积合理（内含前端与依赖，通常 150–260MB）：

```powershell
Get-Item app\build\libs\app.jar | Select-Object Name, @{n='SizeMB';e={[math]::Round($_.Length/1MB,1)}}
```

## 2. 服务器初始化

以下命令均以 root 或 sudo 执行。

### 2.1 系统更新与时区

```bash
sudo apt update && sudo apt upgrade -y
sudo timedatectl set-timezone Asia/Shanghai
```

### 2.2 配置 swap（重要）

4G 内存跑 AI 应用，建议加 2G swap 作为兜底，避免大文件解析时的瞬时峰值直接触发 OOM Killer：

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

降低 swap 倾向，让它只在真正吃紧时才用（避免正常负载下无谓换页拖慢响应）：

```bash
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-interview-guide.conf
echo 'vm.vfs_cache_pressure=50' | sudo tee -a /etc/sysctl.d/99-interview-guide.conf
sudo sysctl -p /etc/sysctl.d/99-interview-guide.conf
```

验证：

```bash
free -h
swapon --show
```

### 2.3 创建专用用户与目录

**不要用 root 跑应用**：

```bash
sudo useradd --system --create-home --shell /usr/sbin/nologin interview
sudo mkdir -p /opt/interview-guide/dumps
sudo mkdir -p /var/log/interview-guide
sudo chown -R interview:interview /opt/interview-guide /var/log/interview-guide
sudo chmod 750 /opt/interview-guide
```

## 3. 安装 JDK 25

项目使用 **Java 25** 编译（`options.release = 25`），必须装 JDK 25。Ubuntu 26.04 的 archive 里 `openjdk-25` 可用（注意：系统 `default-jdk` 指向的版本不一定与项目匹配，**显式指定 25**）。

装 `jdk-headless` 而不是 `jre-headless`：多几百 MB，但带 `jcmd` / `jmap` / `jstack`，排查内存与线程问题时非常必要。

```bash
sudo apt install -y openjdk-25-jdk-headless
```

验证：

```bash
java -version
# 期望输出包含 openjdk version "25.x.x"
```

确认 `java` 路径（后面 systemd 里会用到）：

```bash
readlink -f "$(which java)"
# 通常为 /usr/lib/jvm/java-25-openjdk-amd64/bin/java
```

## 4. 上传应用与配置文件

### 4.1 上传 jar

在你**本机**执行（把 `user`、`你的服务器IP` 换成实际值）：

```powershell
scp app\build\libs\app.jar user@你的服务器IP:/tmp/app.jar
```

然后在服务器上移动到位并修正属主：

```bash
sudo mv /tmp/app.jar /opt/interview-guide/app.jar
sudo chown interview:interview /opt/interview-guide/app.jar
sudo chmod 640 /opt/interview-guide/app.jar
```

### 4.2 编写 `.env`

`.env` 里放**所有环境相关配置**，权限设为仅属主可读（里面是数据库密码和登录密码）：

```bash
sudo -u interview tee /opt/interview-guide/.env > /dev/null << 'EOF'
# ========== PostgreSQL（云端）==========
POSTGRES_HOST=你的云数据库地址
POSTGRES_PORT=5432
POSTGRES_DB=interview_guide
POSTGRES_USER=数据库用户名
POSTGRES_PASSWORD=数据库密码
# 云端连库必须 require；本地无 SSL 才用 disable
POSTGRES_SSLMODE=require

# ========== Redis（云端）==========
REDIS_HOST=你的Redis地址
REDIS_PORT=6379
REDIS_PASSWORD=Redis密码

# ========== 对象存储（RustFS / S3 兼容）==========
APP_STORAGE_ENDPOINT=https://你的存储地址
APP_STORAGE_ACCESS_KEY=存储AccessKey
APP_STORAGE_SECRET_KEY=存储SecretKey
APP_STORAGE_BUCKET=interview-guide

# ========== 登录认证（必填，不填则无法登录）==========
ADMIN_USERNAME=admin
ADMIN_PASSWORD=换成强密码_不要用admin
# 认证开关，公网必须保持 true
APP_AUTH_ENABLED=true

# ========== 反向代理与同源配置（必填）==========
# 1) 让后端从 X-Forwarded-For 取真实客户端 IP。
#    不配的话所有请求的远端 IP 都是 127.0.0.1，
#    会导致按 IP 的限流（含登录防爆破）退化成全站共用一个桶 —— 见第 8.2 节。
SERVER_FORWARD_HEADERS_STRATEGY=framework
# 2) WebSocket 握手会校验 Origin，必须包含你的正式域名，否则语音面试连不上。
CORS_ALLOWED_ORIGINS=https://你的域名

# ========== 可选调优 ==========
# 并发 5 以内，连接池 5 足够（项目默认 3 偏保守）
APP_HIKARI_MAX_POOL_SIZE=5
EOF

sudo chmod 600 /opt/interview-guide/.env
sudo chown interview:interview /opt/interview-guide/.env
```

> **注意**：`.env` 的值**不要加引号**，systemd 的 `EnvironmentFile` 对引号的处理与 shell 不同，裸值最稳。

### 4.3 三个必须改的项

| 配置项 | 不改的后果 |
| --- | --- |
| `ADMIN_PASSWORD` | 留空时登录接口一律拒绝；用 `admin` 则等于公网裸奔 |
| `SERVER_FORWARD_HEADERS_STRATEGY=framework` | 限流按 127.0.0.1 统计，一个人就能把所有人锁在登录页外 |
| `CORS_ALLOWED_ORIGINS=https://域名` | WebSocket 握手被拒，语音面试不可用 |

## 5. 配置 systemd 服务

创建 `/etc/systemd/system/interview-guide.service`：

```bash
sudo tee /etc/systemd/system/interview-guide.service > /dev/null << 'EOF'
[Unit]
Description=AI Interview Guide (Spring Boot)
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=interview
Group=interview
WorkingDirectory=/opt/interview-guide
EnvironmentFile=/opt/interview-guide/.env

# 用 JDK 25 的绝对路径：系统存在多个 JDK 时 /usr/bin/java 可能指向其他版本，
# 会导致 UnsupportedClassVersionError 启动失败。路径以第 3 节 readlink -f 的输出为准。
ExecStart=/usr/lib/jvm/java-25-openjdk-amd64/bin/java -server \
  -Xms512m -Xmx1024m \
  -XX:MaxMetaspaceSize=320m \
  -XX:MaxDirectMemorySize=192m \
  -Xss512k \
  -XX:+UseG1GC \
  -XX:+UseCompactObjectHeaders \
  -XX:+HeapDumpOnOutOfMemoryError \
  -XX:HeapDumpPath=/opt/interview-guide/dumps \
  -XX:+ExitOnOutOfMemoryError \
  --enable-native-access=ALL-UNNAMED \
  -Dfile.encoding=UTF-8 \
  -Dstdout.encoding=UTF-8 \
  -Dstderr.encoding=UTF-8 \
  -Duser.timezone=Asia/Shanghai \
  -Dlogging.file.name=/var/log/interview-guide/app.log \
  -jar /opt/interview-guide/app.jar \
  --server.address=127.0.0.1

# 应用配置了 30s 优雅停机，留足时间不中断在途请求
TimeoutStopSec=45
KillSignal=SIGTERM
SuccessExitStatus=143

# 异常退出自动拉起
Restart=on-failure
RestartSec=10

# 句柄与内存上限（MemoryMax 是兜底，防止 JVM 失控拖垮整机）
LimitNOFILE=65535
MemoryHigh=1800M
MemoryMax=2300M

StandardOutput=journal
StandardError=journal
SyslogIdentifier=interview-guide

[Install]
WantedBy=multi-user.target
EOF
```

启动并设为开机自启：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now interview-guide
```

观察启动日志（首次启动会跑 Flyway 数据库迁移，需要一点时间）：

```bash
sudo journalctl -u interview-guide -f
```

**启动成功的标志**（在日志中确认这三条）：

```
登录认证已启用：/api 接口需登录后访问
Started ... in xx seconds
Tomcat started on port 8080 (http) with context path ''
```

本机验证后端已就绪：

```bash
curl -s http://127.0.0.1:8080/actuator/health
# 期望：{"status":"UP"}
```

## 6. Nginx 反向代理 + HTTPS

### 6.1 安装

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
```

### 6.2 站点配置（先配 HTTP，证书交给 certbot 生成）

**第一步只配 80 端口**。此时证书文件还不存在，若直接写 `ssl_certificate` 会让 `nginx -t` 失败，进而卡住整个流程。certbot 会在签发成功后自动新增 443 块，并**完整复制下面这些 location 规则**。

创建 `/etc/nginx/sites-available/interview-guide`（把 `你的域名` 换成实际域名）：

```bash
sudo tee /etc/nginx/sites-available/interview-guide > /dev/null << 'EOF'
server {
    listen 80;
    server_name 你的域名;

    # certbot 的 HTTP-01 校验路径
    location /.well-known/acme-challenge/ {
        root /var/www/html;
    }

    # 项目 multipart 上限 50MB，此处留出余量
    client_max_body_size 60m;

    # 安全响应头
    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options SAMEORIGIN always;
    add_header Referrer-Policy strict-origin-when-cross-origin always;

    # ---- 运维端点与接口文档：不对公网开放 ----
    # /actuator 暴露了 metrics/prometheus（运行指标），Swagger 暴露全部接口清单
    location = /actuator/health {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        access_log off;
    }
    location ^~ /actuator/ { return 404; }
    location ^~ /swagger-ui { return 404; }
    location ^~ /v3/api-docs { return 404; }

    # ---- 应用主入口 ----
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;

        # 真实来源信息，配合后端 SERVER_FORWARD_HEADERS_STRATEGY=framework 使用
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host  $host;

        # WebSocket（语音面试 /ws/voice-interview/{sessionId}）
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection $connection_upgrade;

        # SSE 流式响应（AI 面试对话）：关闭缓冲，否则前端会「攒着一次性吐出」
        proxy_buffering off;
        proxy_cache off;
        proxy_set_header X-Accel-Buffering no;

        # AI 调用耗时较长（前端上传超时设的是 300s），代理侧保持对齐
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        proxy_connect_timeout 15s;
    }
}
EOF
```

`$connection_upgrade` 变量需要先在 `http` 块定义。编辑 `/etc/nginx/nginx.conf`，在 `http {` 内加入：

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}
```

启用站点并检查（若默认站点占用了 80 端口需先移除）：

```bash
sudo rm -f /etc/nginx/sites-enabled/default
sudo ln -sf /etc/nginx/sites-available/interview-guide /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

### 6.3 申请证书

域名需已解析到服务器 IP。

```bash
sudo certbot --nginx -d 你的域名
```

交互中选择 **Redirect**（将 HTTP 重定向到 HTTPS）。certbot 会自动新增 443 块、写入证书路径、配置续期，并把 6.2 节的全部规则复制过去。

签发后核对 443 块是否完整保留了关键指令：

```bash
sudo nginx -T | sed -n '/listen 443/,/^}/p' | head -60
```

重点确认三处：`client_max_body_size`、`Upgrade`/`Connection` 头、`proxy_buffering off`。缺哪条就按 6.4 节补齐。

验证自动续期：

```bash
sudo certbot renew --dry-run
```

### 6.4 HTTPS 块参考配置

certbot 复制后的 443 块结构应与此一致，可对照补全：

```nginx
server {
    listen 443 ssl;
    http2 on;
    server_name 你的域名;

    ssl_certificate     /etc/letsencrypt/live/你的域名/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/你的域名/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;

    client_max_body_size 60m;

    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options SAMEORIGIN always;
    add_header Referrer-Policy strict-origin-when-cross-origin always;

    location = /actuator/health {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        access_log off;
    }
    location ^~ /actuator/ { return 404; }
    location ^~ /swagger-ui { return 404; }
    location ^~ /v3/api-docs { return 404; }

    location / {
        # 与 6.2 节完全相同的 proxy_pass 与各 proxy_set_header / 超时设置
    }
}
```

> 这里**没有** `listen [::]:443 ssl;`：若服务器禁用了 IPv6，声明 IPv6 监听会导致 Nginx 启动失败。确认系统已启用 IPv6 时可自行加上。

### 6.5 防火墙

**只开放 22 / 80 / 443**，8080 绝不能对公网开放：

```bash
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw --force enable
sudo ufw status verbose
```

> 云服务商的安全组也要做同样限制（安全组与 ufw 是两层，都要配）。

## 8. 资源参数说明（4 核 4G / 并发 5）

### 8.1 JVM 参数为什么这么设

| 参数 | 取值 | 依据 |
| --- | --- | --- |
| `-Xms512m -Xmx1024m` | 堆 1G | 项目自身文档实测 `-Xmx384m` 即可运行（常驻 0.4–0.8G）。给到 1G 是为了覆盖 Tika 解析大文件、向量处理的瞬时峰值，同时不挤压系统内存 |
| `-XX:MaxMetaspaceSize=320m` | 元空间上限 | Spring AI / Tika / MapStruct 加载类较多，默认无上限容易缓慢上涨 |
| `-XX:MaxDirectMemorySize=192m` | 堆外内存上限 | Netty（Redisson）与文件 IO 使用堆外内存。**不设的话默认等于堆大小**，等于隐性多占 1G |
| `-Xss512k` | 线程栈 | 项目已启用虚拟线程，平台线程数量少；缩小栈可省内存 |
| `-XX:+UseG1GC` | G1 收集器 | 4 核场景比项目 `run.sh` 用的 SerialGC 更合适；堆 1G 时 G1 的停顿更可控 |
| `-XX:+UseCompactObjectHeaders` | 紧凑对象头 | **JDK 25 正式特性（JEP 519）**，对象头由 12–16 字节压到 8 字节，实测堆占用降 15–25%。注意它在 JDK 25 中**默认未开启**，必须显式加 |
| `-XX:+HeapDumpOnOutOfMemoryError` | OOM 时留档 | 内存问题时没有 dump 几乎无法定位 |
| `-XX:+ExitOnOutOfMemoryError` | OOM 后退出 | 配合 `Restart=on-failure` 自动拉起，避免进程「僵而不死」 |
| `--enable-native-access=ALL-UNNAMED` | 原生访问许可 | 项目 `bootRun` / 测试均带此参数（存在 native 库调用），运行时保持一致以免告警或失败 |
| `--server.address=127.0.0.1` | 只监听本机 | 后端不对公网直接暴露，所有流量必须经 Nginx |

内存预算（估算）：

```
堆 1024M + 元空间 ~250M(上限 320M) + 堆外 192M + Code Cache ~120M + JVM 自身 ~100M
≈ 1.7G；systemd MemoryMax 设为 2300M 留出弹性，系统与 Nginx 约占 0.5–0.8G
总占用约 2.3–2.5G，在 3G 可用内存下留有安全余量
```

### 8.2 反向代理下的限流（务必理解这一点）

项目限流默认取 `request.getRemoteAddr()`，等价于 TCP 连接来源。若不配置 `SERVER_FORWARD_HEADERS_STRATEGY`：

```
浏览器 → Nginx → 后端  ⇒  后端看到的来源 IP 永远是 127.0.0.1
```

后果是**所有客户端共用一个限流桶**。登录接口限流为「10 次/分钟」，这意味着一台机器反复尝试错误密码，就能让**全部正常用户**在 1 分钟内无法登录。

配置 `SERVER_FORWARD_HEADERS_STRATEGY=framework` 后，Spring 会注册 `ForwardedHeaderFilter`，依据 `X-Forwarded-For` 还原真实客户端 IP。这依赖两个前提，本方案都已满足：

1. Nginx 传递 `X-Forwarded-For`（第 6.2 节配置已包含）；
2. 后端**只能被 Nginx 访问**（已用 `--server.address=127.0.0.1` + 防火墙保证）。

若后端能被公网直连，客户端可自行伪造 `X-Forwarded-For` 绕过限流，此时策略必须改用 `native` 并配合可信代理白名单。

### 8.3 应用自身的低内存配置（已内置，无需改动）

`application.yml` 中已为小规格机器做好准备：

- `spring.threads.virtual.enabled: true` —— 虚拟线程处理请求，Tomcat 线程池不再是瓶颈；
- `server.tomcat.threads.max: 10` —— 非虚拟线程回退场景下的上限；
- `hikari.maximum-pool-size: 3` —— 空闲连接也占内存，用 `APP_HIKARI_MAX_POOL_SIZE=5` 按需调大；
- `spring.jpa.open-in-view: false` —— 避免长时间占有数据库连接。

### 8.4 可选进阶：AOT Cache 加速启动

JDK 25 的 AOT Cache（Project Leyden）可把类加载/链接/方法剖析结果缓存下来，**启动时间约减少三分之一**，Spring Boot 官方推荐优先使用它（Java 25+ 已取代 CDS）。

代价是需要一次训练运行，且**单命令方式会 fork 一个同样大小的堆来做组装**（JEP 514），内存紧张时建议用两步法，或训练时临时降低 `-Xmx`。

```bash
cd /opt/interview-guide
# 1) 解包（Spring Boot 官方推荐在解包形态下训练）
sudo -u interview java -Djarmode=tools -jar app.jar extract --destination extracted

# 2) 训练并生成缓存（会启动应用，刷新完成后自动退出）
cd extracted
sudo -u interview java -Xmx512m -XX:AOTCacheOutput=/opt/interview-guide/app.aot \
  -Dspring.context.exit=onRefresh -jar app.jar --server.address=127.0.0.1

# 3) 生产启动时加载缓存：在 systemd 的 ExecStart 中追加
#    -XX:AOTCache=/opt/interview-guide/app.aot
#    并把 -jar 指向 /opt/interview-guide/extracted/app.jar
```

**注意**：应用每次更新（换 jar）后缓存即失效，需要重新训练。如果觉得维护成本偏高，跳过此项不影响功能。

### 9.4 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 启动失败，日志报 `missing POSTGRES_PASSWORD` | `.env` 未生效或缺少必填项，检查路径与权限（`sudo -u interview cat /opt/interview-guide/.env`） |
| 启动失败，报表结构校验不通过 | 实体与数据库不一致；确认 Flyway 迁移是否执行成功 |
| 页面能打开但没有数据、接口报 401 | 未登录，或 token 已过期被清除，重新登录即可 |
| 登录提示「服务端尚未配置管理员密码」 | `.env` 里 `ADMIN_PASSWORD` 为空 |
| 语音面试连不上 | `CORS_ALLOWED_ORIGINS` 未包含正式域名（WebSocket 握手校验 Origin），或 Nginx 缺少 `Upgrade`/`Connection` 头 |
| AI 回复「卡住不输出」 | Nginx 的 `proxy_buffering off` 未生效（SSE 被缓冲） |
| 登录接口频繁报「请求过于频繁」 | 命中 IP 限流（10 次/分钟）；若未配 `SERVER_FORWARD_HEADERS_STRATEGY`，则是全站共用桶，参见 8.2 |
| 上传文件失败 | Nginx `client_max_body_size` 小于文件（项目上限 50MB，示例配 60m） |

## 附录 A：没有域名怎么办

HTTPS 需要域名。若暂时没有：

1. **推荐**：申请免费域名（如 DuckDNS）解析到服务器 IP，再走第 6.3 节签证书；
2. **临时方案**：自签证书 + 浏览器手动信任，或仅在防火墙上把你的固定 IP 加入白名单访问。

**不建议长期使用纯 HTTP**：登录 token 通过请求头明文传输，公网环境会被中间人截获，等同于账号泄露。

## 附录 B：迁移到其他机器

只需迁移三样东西：`app.jar`、`.env`、`systemd` 服务文件。数据库与对象存储都在云端，无需迁移数据。

## 附录 C：回滚

`app.jar` 替换前先备份上一个版本即可秒级回滚：

```bash
sudo cp /opt/interview-guide/app.jar /opt/interview-guide/app.jar.bak
# 出问题时
sudo systemctl stop interview-guide
sudo cp /opt/interview-guide/app.jar.bak /opt/interview-guide/app.jar
sudo systemctl start interview-guide
```

> 注意：若新版本包含 Flyway 迁移（新增表/字段），回滚旧 jar 前需确认旧版本能兼容已变更的表结构，必要时先在数据库侧回退迁移。
