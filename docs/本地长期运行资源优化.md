# 本地长期运行：资源占用优化指南

> 结论先行：长期运行的资源大头不是应用本身，而是「Gradle Daemon + Worker（约 950MB）」和「Vite dev server（约 600MB）」。
> 改用 **`java -jar` 直跑后端 + Spring Boot 托管前端构建产物** 后，常驻内存可从 ~2.2GB 降到 **单个 JVM（约 500–800MB）+ 0 个 Node 进程**。

## 资源占用从哪来（实测拆解）

| 进程                      | 身份                     | 内存   | 能否省掉                     |
| ------------------------- | ------------------------ | ------ | ---------------------------- |
| Gradle Daemon             | `bootRun` 的常驻父进程    | ~640MB | ✅ 改用 java -jar            |
| Gradle Worker Daemon      | 编译/测试残留 worker      | ~300MB | ✅ 同上（按需构建后退出）     |
| Spring Boot 应用          | 真正的后端               | ~700MB | 保留，限制堆上限             |
| Vite dev server(esbuild)  | 前端开发服务             | ~600MB | ✅ 改用构建产物静态托管       |

（另有 Playwright MCP 等 IDE 工具 Node 进程，与应用运行无关。）

## 长期运行模式（推荐）

### 1. 构建一次

在项目根目录（PowerShell 7）执行：

```powershell
./gradlew :app:bootJar --no-daemon      # 产物：app/build/libs/app-1.0.0-SNAPSHOT.jar
cd frontend; pnpm run build; cd ..      # 产物：frontend/dist
```

### 2. 一条命令启动（后端 + 前端，仅 1 个 Java 进程）

```powershell
.\scripts\run-backend.ps1 -ServeFrontend
```

脚本行为：加载根目录 `.env` → 以 `-Xmx768m` 直跑 jar（无 Gradle Daemon）→ 开启静态托管。
访问 <http://localhost:8080> 即前端页面；`/api/*`、`/ws/*` 由后端处理，同源无需 CORS/Vite 代理。

可选参数：`-Xmx 512`（更省内存，AI 高并发场景慎降）。

### 3. 原理说明

- **`app.static-frontend.*` 配置**（`application.yml`）：`APP_STATIC_FRONTEND_ENABLED=true` 时，
  `StaticFrontendConfig` 将 `frontend/dist` 挂为 `/**` 静态资源并提供 SPA fallback（未命中文件回退 `index.html`）。
  默认关闭，不影响开发模式与既有部署（v1.0 起本地统一走「本地零 Docker 启动」，中间件走云端；旧 docker-compose 方案已归档至 `docs/legacy-docker/`）。
- 前端 API 全部走相对路径 `/api/*`，WebSocket 从 `window.location.host` 推导，同源托管下零改动可用。

## 开发模式（改代码时）：也把 Gradle 内存压下来了

`gradle.properties`：

- Daemon 堆 `2g → 512m`（单模块构建足够），新增 `org.gradle.daemon.idletimeout=600000`
  （空闲 10 分钟自动退出，不会常驻一下午）。
- `bootRun` JVM 显式 `-Xmx768m -XX:MaxMetaspaceSize=256m`（原先不限制，默认吃 1/4 物理内存）。

临时查 daemon：`./gradlew --status`；手动清掉所有常驻：`./gradlew --stop`。

## 稳态运行本身没有多余的浪费（审计结论）

- Redis Stream 消费为阻塞式 `readGroup`（1s block）而非忙轮询；5 个消费者各 2 线程，daemon 线程，开销可忽略。
- `@Scheduled` 共 4 个，最密为语音面试会话保活每 30s 一次，遍历内存 Map，无压力。
- Redisson 连接池已是最小化配置（5 idle）；LLM 客户端按 provider 缓存，无重复构建。

## 快速对比

| 模式                     | 常驻进程            | 常驻内存（估）  |
| ------------------------ | ------------------- | --------------- |
| 旧：bootRun + vite dev   | 2 Java + 1~2 Node   | ~2.2 GB         |
| 新：java -jar + 静态托管 | 1 Java              | ~0.6–0.8 GB     |
| 新：java -jar（不托管）  | 1 Java              | ~0.5–0.7 GB     |
