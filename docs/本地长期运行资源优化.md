# 本地长期运行：资源占用优化指南

> 结论先行：长期运行的资源大头不是应用本身，而是「Gradle Daemon + Worker（约 950MB）」和「Vite dev server（约 600MB）」。
> 需要长时间挂机时，用 `bootJar` 产出单个 **`app.jar`**（前端静态资源已内置），再用 `run.bat` 低内存直跑，
> 常驻内存可从 ~2.2GB 降到 **单个 JVM（约 400–800MB）+ 0 个 Node 进程**。

> 本文档描述 **main 分支（v1.0 起，本地零 Docker 启动）** 的运行机制；旧版 Docker 方案见 `docs/legacy-docker/`。

## 资源占用从哪来（实测拆解）

| 进程                      | 身份                     | 内存   | 能否省掉                     |
| ------------------------- | ------------------------ | ------ | ---------------------------- |
| Gradle Daemon             | `bootRun` 的常驻父进程    | ~640MB | ✅ 改用 run.bat（java -jar） |
| Gradle Worker Daemon      | 编译/测试残留 worker      | ~300MB | ✅ 按需构建后退出             |
| Spring Boot 应用          | 真正的后端               | ~700MB | 保留，run.bat 限制堆上限      |
| Vite dev server(esbuild)  | 前端开发服务             | ~600MB | ✅ 前端已内置进 app.jar       |

（另有 Playwright MCP 等 IDE 工具 Node 进程，与应用运行无关。）

## 长期运行模式（推荐，main 机制）

### 1. 构建一次

在项目根目录（PowerShell 7）执行：

```powershell
.\gradlew.bat :app:bootJar --no-daemon      # 产物：app/build/libs/app.jar
```

`bootJar` 依赖 `buildFrontend`（`pnpm run build`）与 `syncFrontendStatic`：
`Sync` 任务自动把 `frontend/dist` 同步到 `app/src/main/resources/static`，**前端无需单独起 dev server**，
也**没有**任何静态托管脚本（`scripts/` 下仅有 git hook 校验脚本，无 `run-backend.ps1`）。

### 2. 一条命令启动（后端 + 前端，仅 1 个 Java 进程）

```powershell
.\run.bat
```

脚本行为：加载根目录 `.env` → 自动重新构建 `app.jar`（前端未变化时 Gradle 跳过 pnpm build）→
以 `-Xms128m -Xmx384m -XX:MaxMetaspaceSize=256m -Xss256k -XX:+UseSerialGC` 低内存配置直跑 jar。
访问 <http://localhost:8080> 即完整应用；`/api/*`、`/ws/*` 同源，无需 CORS/Vite 代理。

> JDK 定位：`run.bat` 优先使用环境变量 `%JAVA_HOME%`（指向 JDK 25 安装目录），未设置时回退 PATH 上的 java。

### 3. 原理说明

- **静态资源内置**：`syncFrontendStatic` 把 `frontend/dist` 同步进 `classpath:/static`，
  `SpaWebConfig` 提供 SPA fallback（未命中文件回退 `index.html`）。
  早期实现 `StaticFrontendConfig` / `APP_STATIC_FRONTEND_ENABLED` 已不存在，勿再引用。
- 前端 API 全部走相对路径 `/api/*`，WebSocket 从 `window.location.host` 推导，同源托管下零改动可用。

## 开发模式（改代码时）：控制 Gradle 内存

`gradle.properties`（机器相关，内含本机 JDK 绝对路径，已 git 忽略）：

- Daemon 堆为 `-Xmx2g`（单模块构建足够）；如需更省可自行调低为 `-Xmx512m`，
  并追加 `org.gradle.daemon.idletimeout=600000`（空闲 10 分钟自动退出，不会常驻一下午）。
- `bootRun` 的 jvmArgs 当前只固定编码与日志参数（`-Dfile.encoding=UTF-8`、`-Dlogging.file.name=logs/app.log`），
  **未显式设置堆上限**，本地调试时默认吃 1/4 物理内存，长时间挂着建议改用上面的 run.bat 方式。

临时查 daemon：`./gradlew --status`；手动清掉所有常驻：`./gradlew --stop`。

## 稳态运行本身没有多余的浪费（审计结论）

- Redis Stream 消费为阻塞式 `readGroup`（1s block）而非忙轮询；5 个消费者各 2 线程，daemon 线程，开销可忽略。
- `@Scheduled` 共 4 个，最密为语音面试会话保活每 30s 一次，遍历内存 Map，无压力。
- Redisson 连接池已是最小化配置（5 idle）；LLM 客户端按 provider 缓存，无重复构建。

## 快速对比

| 模式                     | 常驻进程            | 常驻内存（估）  |
| ------------------------ | ------------------- | --------------- |
| 旧：bootRun + vite dev   | 2 Java + 1~2 Node   | ~2.2 GB         |
